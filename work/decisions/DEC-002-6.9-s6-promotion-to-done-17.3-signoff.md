## Rationale

1. **Route (a) — a further reviewed `_select_skills` quality PR — is a proven
   dead end.** PR #260's pre-implementation scoring simulation against the
   frozen corpus (confirmed by @soda) and PR #264's independent gate re-run both
   establish that the two residual gaps are not lexically closeable without
   regressing an already-passing category:
   - **VOCABULARY_SHIFT (EXPB-V01):** a plural/tense lemmatiser reduces V01's
     match to the single token `credential`→`credentials` (weight 1.0), which is
     lexically identical to hard negatives EXPB-H02 (`rotation`→`secrets-rotation`)
     and EXPB-H03 (`api`→`api-contract-review`). Any strength floor that admits
     V01 re-admits H02/H03 → HARD_NEGATIVE regresses. V02–V04 need true synonymy
     (`brownout≈outage`, `soak≈load`, `payload shape≈contract`) — no
     morphological path exists.
   - **AMBIGUOUS (EXPB-A01/A02):** these are not score-ties (token evidence
     favours one candidate). A margin rule loose enough to flag them also flags
     EXPB-M01, a genuine legitimate multi-Skill tie → MULTI_SKILL regresses from
     1.00.
   Both require query expansion / semantic similarity, which is roadmap **§6.33**
   — a separate item with its own evidence gate. Chasing it inside 6.9 would
   pre-empt that gate.

2. **#250's single dispositive NO-FLIP item is resolved.** At #250, HARD_NEGATIVE
   was 0.00 (4/4 false activations — "a selector with zero relevance
   judgement"), and aggregate f1 was 0.722 ("middling"). Post-#260: HARD_NEGATIVE
   1.00, `false_activation_cases` 0, f1 0.867. The one safety-relevant failure is
   closed and the aggregate clears any reasonable P2 floor.

3. **§17.3 names "explicit operator decision" as a valid status-evidence type**,
   and this is precisely the mechanism for promoting a capability with a
   characterized, accepted limitation whose closure belongs to a different
   roadmap item. Whether synonym-shift and fine-grained-ambiguity routing are
   inside §6.9's DONE bar or belong to §6.33 is a scope-boundary authority call,
   not a code question — the operator's to make, not a reviewer's.

4. **S6 exit gate is MET.** "Unrelated Skills demonstrably stay out of context":
   EXP-B post-#260 shows `false_activation_cases` 0, HARD_NEGATIVE 1.00,
   NO_SKILL 1.00; `tests/test_context_builder.py` asserts the unrelated-Skill
   exclusion directly.

5. **§6.9 promotion gate is satisfied.** "Do not rely on fuzzy Skill selection
   without a frozen selection evaluation" — EXP-B exists, is sha256-pinned, runs
   the real `_select_skills` through the real `evaluate_skill_selection`, and
   covers all six "must include" categories with ≥4 cases each.

## Containment (why the residual is safe to ship)

The residual is a routing-*correctness* gap, not a safety gap. Selection sits
*upstream* of two independent gates that bound the blast radius:

- **6.22 memory/Skill trust gate** — `admit_memory_evidence()` decides
  LOAD/WITHHOLD/DENY per matched Skill after selection.
- **SEC4 quarantine lifecycle** — a `QUARANTINED`/`RETIRED`/`SUPERSEDED` Skill
  is DENY'd out of a real `maps flow start` context plan.

A missed activation (VOCABULARY_SHIFT) degrades to "the operator's own explicit
Skill reference still works"; it never causes an unsafe load. An unlabelled
ambiguity (AMBIGUOUS) surfaces the higher-scoring candidate as attributed
evidence, not as authority.

## Deferred to §6.33 (explicit)

`VOCABULARY_SHIFT` (pure synonym shift) and `AMBIGUOUS` (fine-grained
disambiguation) routing are deferred to roadmap **§6.33 — Semantic retrieval /

("a frozen evaluation must demonstrate meaningful improvement over
explicit/baseline"). This decision does **not** change §6.33's status.
