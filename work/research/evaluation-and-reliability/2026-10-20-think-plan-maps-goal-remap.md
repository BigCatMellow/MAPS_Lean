### Retrieval and recursion convention (for this research tree only)

- **Start at this index.** Follow the direct link for the named node or question; read its immediate dependencies only when relevant. No need to load every branch or follow all parents first.
- **Stable IDs identify logical nodes.** Files are physical storage. A node can recurse through as many levels as necessary without creating the same number of directories/files.
- **Promote a subtree to a separate child file** only when it has a distinct, substantial question or evidence set; use B2 and E2 as examples. Its old owner becomes a short pointer, not a second editable copy.
- **Single factual owner:** don't maintain duplicate descriptions of a node. Cross-branch conditions are links in [Dependencies](2026-10-20-maps-remap/DEPENDENCIES.md), not duplicate subtrees.
- **Statuses are dated assessments, never live task truth.** Recheck current code, CI, accepted authority, PR reviews, and requirements before converting a candidate into approved work.

No automatic index generator or runtime navigation mechanism is asserted: this is a **hand-maintained one-hop index** for a bounded research package. Automation should be added only when update volume demonstrates that it would reduce errors more than it costs.
