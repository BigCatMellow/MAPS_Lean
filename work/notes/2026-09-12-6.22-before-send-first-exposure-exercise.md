## Caveat A (stated plainly, not hidden): the guard fired on its inert branch, not a denying one

The fixture task had no recorded `guidance`/`withheld_guidance`/`skills`, so
`render_context_send_payload` produced `memory_provenance: []` and omitted
the `memory_content` marker (`has_memory` was `False`). Per
`MemoryProvenanceGuard.__call__`, an empty/absent provenance with no
`memory_content` marker takes the `GUARD_CODE_ALLOW_NO_MEMORY` ("Payload
carries no memory-derived content") branch — the guard's own docstring calls
this "inert." **The `BEFORE_SEND` hook demonstrably fired and the guard
callback demonstrably executed for the first time via a real caller** (proven
by `before.permitted` gating a real `adapter.send()` that a live session
received), but this run does **not** exercise the guard's `LOAD`/`WITHHOLD`/
`DENY` re-derivation branches — that would need a task with real recorded
memory-like evidence (a lesson/guidance item with a trust class) feeding
`build_context_plan`, which is a materially larger fixture-construction task
than this bounded exercise's scope, and was not attempted here. This is the
same class of honest caveat as the 6.16 precedent's Caveat B (induced vs.
organic exposure) — not a reason to claim more than what was shown.

## Caveat B: `CanonicalRunGuard` also fired concurrently

`build_canonical_harness_service` composes `CanonicalRunGuard` on the same
`BEFORE_SEND` event. `_require_canonical_enforcement` also passed (the guard
requires evidence the canonical-run enforcement is live, which
`--enforce-canonical-run` + a bound run/lease satisfies). Both hooks ran in
the same `hooks.run()` call; there is no per-hook firing breakdown in the
CLI's JSON output (same flattening limitation the 6.16 note's Caveat A
described for `recovery-tick`). `MemoryProvenanceGuard` specifically firing
is an inference from (a) its unconditional composition in
`build_canonical_harness_service`, read directly in
`runtime/recovery/production.py`, and (b) `before.permitted == True` gating
the observed `adapter.send()` call — not a field read off the command's own
output. Same disclosure standard as 6.16 Caveat A.
