## Required outcome
A new operator can use MAPS_L's approved methods on a previously unmanaged repository while keeping that project's state separate, its task boundary clear, and its workflow independently operable. Later scale must be earned by successful single-project use.

## Recursive conditions
- **H08.1 — Shortest useful onboarding route.** Plain-language entry point, known requirements, installer preview, explicit target and recovery path. **Proof:** a fresh operator can bootstrap without searching through legacy or several competing playbooks.
- **H08.2 — Portable v1 design decisions retained.** Lightweight committed-in-target file convention, sibling clone + adapter, best-effort review evidence for v1, stack-agnostic entry, not wholesale SQLite copying. **Proof:** implementation matches the accepted 2026-08-19 decisions or records a separately authorized change.
- **H08.3 — One real external project end-to-end.** [Open H08.3](H08.3-external-v1.md) for target authorization, isolation, task execution, independent review and proof. This is a **necessary early program test**, not the whole MAPS_L end state.
- **H08.4 — Operator friction and continuity.** Humans only step in for a material authority/subjective decision, not every worker task. **Proof:** count interventions, ambiguous waits, repeated setup and manual coordination without declaring any arbitrary autonomy percentage.
- **H08.5 — Port review/CI to other ecosystems conditionally.** Trigger D4 onboarding packs and D5 alternate CI on actual target compatibility needs.
- **H08.6 — Fleet management as earned scale.** D6 only after safe, durable single-project results and measurable cross-project demand.
- **H08.7 — Serviceability.** Correct install/uninstall, stable state ownership, rollback, troubleshooting and safe defaults. **Proof:** fresh agent/operator replicates a bounded task without privileged ad-hoc fixes.
