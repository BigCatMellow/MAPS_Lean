## Required outcome
A concise human objective becomes a correct, constrained, testable project/task strategy. Ambiguity becomes an explicit question or bounded investigation—not invented permission or unneeded work.

## Recursive conditions
- **H01.1 — Recover actual request and context.** Resolve "continue," "next blocker," and references against live canonical project/task evidence; use minimal context. **Proof:** independent agent recovers the same intended objective without assuming old thread prose is task truth.
  - **H01.1.1** Identify principal user-visible outcome and beneficiaries.
  - **H01.1.2** Distinguish directly stated intent from inferred assumptions and unknowns.
  - **H01.1.3** Resolve an existing request to its actual project, active scope and permitted action.
- **H01.2 — Preserve human authorization.** Required credentials, external effects, destructive scope, monetary spend and subjective preferences remain human/operator boundaries. **Proof:** a proposed contract cannot authorize what its sources do not authorize.
- **H01.3 — Define observable DONE and non-goals.** Include acceptance, verification, recovery, evidence and maintenance for repeatable work. **Proof:** an independent reviewer can decide success/failure from observable result.
- **H01.4 — Choose the smallest planning resolution.** An already actionable task stays a leaf; only coarse/uncertain/blocked branches expand. **Proof:** less planning overhead without lower successful completion or extra authority violations.
- **H01.5 — Preserve strategy alternatives only when decision-relevant.** Material assumptions, reversal conditions, and evidence are retained, not every brainstormed option. THINK returns when a strategic assumption fails; PLAN repairs execution when the strategy remains valid.
- **H01.6 — Conditional mission/multi-task goal object.** The master roadmap §6.34 is *evidence-gated*, not a default second task hierarchy. **Proof:** a concrete cross-task continuity failure requires it and a proposed minimal view improves that failure against current task state.

## Actual evidence and limits
Existing [Project Bootstrap](../../../../playbook/PROJECT_BOOTSTRAP.md), [operator-intent-compiler planning owner](../../operator-intent-compiler.md), and canonical task state already provide the foundation; production intent compilation is **not** established by its planning document. Pilot THINK/PLAN has not demonstrated production mechanism superiority. Do not silently rewrite the goal around the first portable deployment demonstration.

## Next useful decision
Sample representative human requests and test whether the current shaping/AGI gates already satisfy H01.1–H01.4. Only design an additional compiler or PLAN representation if a recurring measurable miss survives a simpler repair.

## Stop / reversal
Stop expansion when the accepted task is executable and verifiable. Return to THINK only for a falsified strategic assumption; return to the human for a true scope/permission change.
