## Parent
[H09 — Learning and improvement](H09-learning.md). This condition must discriminate real improvement from complexity, confounding and training/evaluator leakage.

- **H09.3.1 — State a falsifiable question.** E.g., does diagnosis-gated plan decomposition or changed harness configuration measurably improve successful accepted work versus the existing MAPS_L task bootstrap?
- **H09.3.2 — Identify versions precisely.** Resolve canonical task revision, run, effective harness config hash, environment, source and artifact. Missing real-run L6 identity → block strong comparisons.
- **H09.3.3 — Freeze a representative case set and baseline.** Include easy and difficult tasks, recovery/security negative cases, direct-control cases and cases where doing nothing is right; blind evaluation where possible.
- **H09.3.4 — Evaluate quality and cost.** Track success, criterion coverage, failure/escape, operator touches, runtime/tokens, regression and confidence/uncertainty. A positive average score at several times the cost is not unqualified improvement.
- **H09.3.5 — Independent challenge.** Check leakage, evaluator ceiling, bad control arm, cross-case contamination, cherry-picked examples and untested transfer to new tasks.
- **H09.3.6 — Reconcile outcome.** ACCEPT | REJECT | NARROW | DEFER with linked evidence; promotion remains human/accepted policy-gated and reversible. A test pass never authorizes changing production safety policies.
