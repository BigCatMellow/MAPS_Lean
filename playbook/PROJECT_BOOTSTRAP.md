# Project Bootstrap

Use for a project expected to span sessions, accumulate multiple tasks, or use
more than one agent. Skip it for a throwaway experiment or small local fix.

## Project flow

**Plan backward. Execute forward.**

1. Define the goal and a concrete definition of **DONE**: what must exist, work,
   or be proven when the project is complete.
2. Work backward from DONE. Ask what must be true immediately before it, then
   what must be true before that. Continue until the chain reaches the current
   state.
3. Turn that backward chain into a forward roadmap. Name phases, dependencies,
   tasks that may run in parallel, final verification, and integration points.
4. Record quality standards, constraints, assumptions, unanswered research
   questions, risks, and decision boundaries.
5. For a multi-agent or consequential project, hold a short **mission meeting**
   before implementation. The accountable owner presents the goal and draft
   roadmap; relevant agents challenge missing steps, dependencies, risks,
   verification, and useful parallel work. The operator resolves decisions that
   affect scope, cost, risk, or user-visible behavior.
6. Revise the roadmap from that meeting and record the first assignments. The
   meeting does not grant authority by itself; the approved project/task records
   remain authoritative.
7. Create locations for tasks, decisions, evidence, handoffs, and useful
   discoveries.
8. Start execution only when the first tasks are clear enough to own, verify,
   and finish.

The mission meeting is a planning check, not ceremony. Do not summon extra
agents for a simple task or invent roles merely to have a meeting.

## Minimum project brain

A new agent should be able to answer:

- What are we making?
- What exactly counts as DONE?
- What is the roadmap from here to DONE?
- What is unknown or risky?
- Who decides what?
- What can happen in parallel?
- How will the final result be verified?
- Where do tasks, decisions, handoffs, evidence, and useful new ideas go?
